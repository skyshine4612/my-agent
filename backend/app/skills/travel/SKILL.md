# 旅行规划

规划旅行/行程时，遵循以下规则：

- 涉及跨城交通（火车/飞机）必须调用 `train_ticket_query` / `flight_query` 查真实车次航班与票价，严禁编造；往返两个方向都要查（如「上海→杭州」和「杭州→上海」），不要只查单程。
- 景点用 `poi_search` 查询，用 `types` 分类码搜（风景名胜=110000、科教文化/博物馆=140000）；只有用户明确说出具体景点名（如「西湖」）时才用 `keywords` 搜。不要用「景点」「寺庙」这类宽泛类别词当 `keywords`（搜不准），也不要凭记忆编具体地名。
- 景点/美食/住宿的推荐只能来自 `poi_search` 实际返回的结果；工具没返回的（如某博物馆、餐厅、酒店）一律不要用外部知识脑补推荐。
- 住宿用 `poi_search` 查「酒店」「民宿」等关键词，列出名称与位置。
- 本地美食用 `poi_search` 查「本地菜」「特色菜」「小吃」等关键词（结合目的地，如杭州用「杭帮菜」、成都用「川菜」；不要用宽泛的「美食」，会返回肯德基等快餐），列出具体餐厅名称与位置；餐厅的招牌菜再用 `poi_detail` 查（按 poi_search 返回的 id），推荐菜只能来自 `poi_detail` 返回的 tag，禁止用记忆编菜名。注意 `poi_detail` 只用于「餐厅」，酒店、景点等其他类型 POI 不要调它。
- 天气用 `weather_query` 查询。
- 本业务不使用 `tavily_search`：交通/天气/景点/住宿/美食均有专用工具，缺失信息如实说明即可，不要转去网页搜索补查。
- 多个独立查询（交通、天气、景点、住宿、美食）应在同一轮并行调用，不要逐个串行等待。
- 默认给 1 套方案即可；只有用户明确要求（如「给几个不同方案」「多套方案」）时才给 2-3 套不同侧重点的方案（如「经典景点游」「美食文化游」「亲子休闲游」），每套都写逐日安排。
- 每套方案附预算表（交通/住宿/餐饮/门票分类列）；某项价格查不到就在表里标注「未查到」，但表格结构必须保留。
- 门票价、房价等 `poi_search` 查不到的，预算表里如实标注「未查到」并说明未计入，不要补查、不要编造具体数字。
- 信息不足时先基于合理假设推断并明确提示用户，不要反复追问。

## 输出格式

每次严格按下面固定结构输出（标题、顺序、层级保持一致，不要每次换排版）：

### {目的地} {N} 日游

**天气**：逐日一行（`{日期} {天气} {白天温度}℃/{夜间温度}℃`，来自 `weather_query`）

**交通**：去程、返程各一行（`{车次/航班} {出发站} {出发时间} → {到达站} {到达时间}，{座位} ¥{票价}`），未查到的方向标「未查到」

**方案**：默认 1 套时直接按 Day1/Day2/... 逐日列出安排（不用「方案一」这种标题）；只有多套时才用 `方案一「{侧重点}」`、`方案二「{侧重点}」` 分标题。末尾附预算表（交通/住宿/餐饮/门票 4 列，查不到的标「未查到」）

**美食**：`{餐厅名}：招牌菜 {菜名}`（菜名来自 `poi_detail`）

**提示**：需提前预订/核实的信息，如实标「未查到」
